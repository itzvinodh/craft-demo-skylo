KEY DESIGN POINTS
================================================================================

1. THREE-TIER ARCHITECTURE
   - Public: NAT (egress) + NLB (ingress, only public surface)
   - Private: EKS nodes, pods (100.64.0.0/16 secondary CIDR), TGW attach
   - Tier separation enforces blast radius (public cannot reach ground/org)

2. PER-AZ ROUTE TABLES (PRIVATE TIER)
   - Why? Each AZ's private subnets point to its own NAT (not shared cross-AZ)
   - Avoids single-AZ failure: if AZ-a fails, AZ-b and AZ-c keep their own NATs
   - Trade-off: 3 route tables instead of 1; worth it for resilience

3. CIDR STRATEGY (Collision Prevention by Construction)
   - Hub VPCs:      10.0.0.0/9      (hub#1=10.100, hub#2=10.101, etc.)
   - Ground:        10.128.0.0/9    (hub#1=10.200, hub#2=10.201, etc.)
   - Org/shared:    172.16.0.0/12   (DIFFERENT RFC1918 block, impossible collision)
   - Pods:          100.64.0.0/16   (RFC 6598, cluster-local, no TGW routing)

4. TGW ATTACHMENT (Segmentation)
   - Two separate TGW route tables: Ground (DX) ≠ Org (east-west)
   - Hub VPC sends both routes toward TGW, but TGW decides which traffic goes where
   - No flat routing table = no accidental cross-segment traffic

5. DATA FLOW EXAMPLE
   a) Device sends session-setup packet over satellite → Ground station (10.200.0.0/16)
   b) Ground station sends over DX → AWS DX endpoint → TGW
   c) TGW matches route 10.200.0.0/16 in Ground route table
   d) TGW forwards to hub VPC (TGW attachment)
   e) Hub VPC: private subnet receives packet from TGW attachment ENI
   f) Data-ingress pod (10.100.15.x / 100.64.x.x) parses packet
   g) Core-network pod (10.100.15.y / 100.64.x.y) queries Redis, decides routing
   h) UPF pod forwards to NLB (100.64.x.z)
   i) NLB sends response to customer via IGW

6. SECURITY BY DESIGN
   - Single public surface: NLB only (on sg-nlb-public SG)
   - EKS nodes: private IPs only, no internet-facing (on sg-eks-private SG)
   - Ground/org traffic: isolated at TGW layer, not mixed in one route table
   - No pod-to-internet: all egress via NAT (controlled, monitorable)

7. SCALABILITY
   - Pod CIDR (100.64.0.0/16) is secondary, not competing with node IPs
   - Each AZ private subnet is /24 (251 usable IPs) — headroom for 100 nodes + buffer
   - Karpenter scales nodes; HPA scales pods; independent scaling on two address spaces
   - As Skylo adds more hubs, CIDR strategy remains collision-free (structural guarantee)
